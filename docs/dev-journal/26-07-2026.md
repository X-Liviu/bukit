## Problemas encontrados y cómo se resolvieron

- **CI roja en su primera ejecución**: `prisma generate` falla cuando el esquema no tiene modelos — y el nuestro está vacío **a propósito** (diseño incremental con el autor). Solución: retirar el paso (los tipos _placeholder_ de `@prisma/client` bastan para el typecheck); vuelve con el primer modelo (US-04). Receta en comentario del workflow.
- **`gh run watch` en segundo plano** permite seguir la CI sin bloquear la sesión (receta para próximas historias).
- **Overfull en el cap. 3 al definir `\ac{HTTP}`**: la expansión de la primera aparición (ahora en el cap. 3 tras reordenarse los capítulos con contenido) alargó una frase cuya lista de rutas `\texttt{packages/...}` no se puede partir, desbordando 28,3 pt el margen. Solución combinada: reordenar la frase, recortar palabras prescindibles y `\allowbreak` tras `packages/` para permitir el corte de las rutas → 0 overfull. Receta para cualquier ruta larga en `\texttt`.
- **Las 10 issues del tablero estaban corrompidas por interpolación de PowerShell**: título y cuerpo mostraban el objeto serializado entero (`@{number=1; title=...}.title`) en vez del texto. Origen: un `gh issue edit` de la sesión que montó el tablero usó `"$issue.title"` en PowerShell 5.1, que expande el objeto completo y pega `.title` como literal. El contenido real (tildes incluidas) seguía intacto dentro de la cadena: script de Node que lo extrae con regex anclada y reescribe las 10 issues vía `gh issue edit --body-file` con argumentos en array (sin shell, para que el UTF-8 viaje bien en Windows). Verificado contra GitHub: 0 corruptas restantes. La milestone F3 tenía el mismo defecto en su título (las otras tres estaban bien): corregida vía `gh api PATCH` y verificadas las cuatro. Receta: en PowerShell, interpolar siempre con `$($obj.prop)`; mejor aún, cuerpos por archivo y argumentos sin shell.
