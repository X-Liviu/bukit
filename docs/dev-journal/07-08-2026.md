## Problemas encontrados y cómo se resolvieron

- **`prisma migrate dev` se niega en entornos no interactivos**: receta usada y documentada — `prisma migrate diff --from-empty --to-schema-datamodel --script` para generar el SQL versionado + `migration_lock.toml` a mano + `migrate deploy` para aplicarlo.
- **Docker Desktop se cayó dos veces durante la sesión**: los 5 tests de integración pasaron a rojo de golpe (el hook `deleteMany` no alcanzaba la BD) simulando una regresión que no existía, y un `|| true` en el comando de humo enmascaró que la build ni había arrancado. Recetas: si TODA una suite de integración cae a la vez, comprobar el daemon antes que el código; y nunca colgar `|| true` del paso cuyo resultado importa.
- **GitHub no conserva los logs de jobs cancelados en caliente** (ni el blob de logs ni el array de pasos): el diagnóstico del cuelgue habría sido imposible sin la nota de la sesión del móvil y sin la reproducción. Receta arriba: pasos en vivo por API antes de cancelar.
- La pantalla «Create a new Service» de Render no es la del Blueprint (habría configurado el servicio a mano, perdiendo el `render.yaml`): el camino correcto es «+ New → Blueprint» o `dashboard.render.com/blueprints`.
